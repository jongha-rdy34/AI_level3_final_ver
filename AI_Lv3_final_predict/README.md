# AI 역량평가 Lv3 — 최종 예측 문제 (공식 샘플 기반)

**실제 시험 문제가 아닙니다.** 2026-11-06 공개된 공식 샘플 5문항의 **형식·제약·채점 방식은 그대로** 두고, 데이터와 함정만 바꿔 "본 시험에 나올 만한" 문제로 만든 연습 세트입니다.

## 1. 예측 근거
| 근거 | 내용 | 반영 |
|---|---|---|
| 공식 샘플 구성 | P1_1·P1_2 데이터, P2_1·P2_2 모델링, P3 프롬프트 (총 5개) | 같은 5개 구성 F1_1 ~ F3 |
| 사전 공지 영역 | 데이터 점검·분포·품질·육안 검사·변환/증강·**학습 데이터 재구성** / 전이학습·학습 범위·**손실 함수 구현**·하이퍼파라미터·성능 분석 / 정규화·미확정 정보·JSON 스키마 | 샘플이 안 다룬 **라벨 오류·중복·품질**(F1_1), **불균형용 Loss**(F2_1)를 넣음 |
| 공식 정보 | TinyViT 5M, 상품 이미지 20분류 | 전 문항 Fashion 상품 이미지(80×60), F1_2·F2_1·F2_2는 20종 |
| 샘플의 함정 유형 | 불균형(P1_1), train/val 분포 차이 + 과한 기본 증강(P1_2), 정정·거절·잘못된 서류(P3) | 같은 유형을 **다른 데이터**로 다시 출제한다고 가정 |
| 샘플 14개 원인 목록 | P1_1에 "데이터 부족, 불균형, 라벨 오류, 낮은 품질, 중복…" 14개가 나열됨 | 이 목록에서 다른 항목이 다음 문제로 나올 가능성이 높다고 봄 |

## 2. 문항
| 문항 | 틀(샘플) | 바뀐 점 | 수정 셀 | 평가 |
|---|---|---|---|---|
| **F1_1** 데이터 정제 | P1_1 (Linear Probing 고정) | 10종. 협력사 사본이 **다른 라벨로** 섞임 + **손상 이미지**(흰/검은/잡음) + **같은 사진 15회 반복** | `train_transform`, `processing_training_data` (제외 허용) | val macro-F1 |
| **F1_2** 분포 차이 | P1_2 (증강만 수정) | 20종. train=스튜디오 상품컷, val=**판매자 앱 사진**(작게·치우침·기울기·어둡게·흑백). 기본 증강에 **해로운 변환**(상하 반전, 확대 crop, 색상 회전) | `train_transform` | val macro-F1 |
| **F2_1** 학습 범위·Loss·HP | P2_1 | 20종 **긴 꼬리 불균형**(800→30장). 학습 범위 `stages[3]+head`. **불균형 대응 Loss 직접 구현** (`class_counts` 제공) | `FashionModel`, `custom_loss`, `batch_size/lr/epochs` | val macro-F1 + 기록 |
| **F2_2** 성능 최대화 | P2_2 (Kaggle) | 20종×400장. **val·test 절반이 앱 사진** | 증강·모델·HP·학습 루프 | test accuracy |
| **F3** 프롬프트 | P3 | **쇼핑몰 반품·교환 상담 → 접수서 22개 항목**. 접수 규정(배송비·환불액 계산), enum 항목(요청유형·사유유형·상품분류 20종) | `system_prompts()` | 형식 통과 + 필드 정확도 |

## 3. 시작하기
1. 옆에 `AI_Lv3_sample_solution` 폴더가 있어야 합니다(같은 `.venv`와 Kaggle 원본을 씀).
2. `setup.cmd` 실행 → `.venv` 연결, 가중치 복사, `data/` 생성, `F3_qa.csv`, `gms_config.pkl` 생성.
3. VSCode에서 **이 폴더**를 열고 커널 `.venv\Scripts\python.exe` 선택.
4. `F*_problem.ipynb`를 풀고 `F*_answer.ipynb`와 비교. CPU면 정답안은 QUICK 모드로 돕니다.
5. F2_2 로컬 채점: `.venv\Scripts\python _grading\score_f2_2.py` (추론 셀이 `test.csv`를 채운 뒤).
6. F3는 본인 GMS 키가 있어야 품질 확인이 됩니다. 정답 비교 셀이 `_grading/f3_truth.json`과 항목별로 비교합니다.

## 5. 핵심 요령 (샘플 + 예측 공통)
- **데이터 문항**: 그림·개수부터 보고(육안 검사) 원인을 하나 정한 뒤, 주어진 함수 틀 안에서만 해결. 무엇을 왜 했는지 **주석·print로 남기기**.
- **증강**: 검증 데이터에서 *실제로 보이는 변화*만, *비슷한 크기*로. 해로운 기본값(과한 이동·shear·지우기, 상하 반전, 색상 회전, 확대만 하는 crop)을 빼는 것도 점수.
- **학습 범위 고정 3종**: `requires_grad_(False)` + 고정 구간 **항상 `eval()`**(BN 통계 보호, `train()` 오버라이드) + `torch.no_grad()`.
- **Loss 직접 구현**: `F.log_softmax` + `gather` + `mean`. `F.cross_entropy` 등 완성형 금지, `detach()/item()` 금지. 반환은 `()` 스칼라.
- **Kaggle 문항**: 추론 셀이 수정 금지여도 **모델 forward 안에 TTA**를 넣을 수 있음.
- **프롬프트**: 형식 규칙(키 목록·`null`·정수·날짜·enum) → 최종 합의/정정 원칙 → 항목별 정의 → 계산 규칙 순서.

- 정답안 코드 셀에는 **줄마다 동작 설명 주석**이 붙어 있습니다(샘플 폴더의 `_build/annotate_answers.py`로 두 폴더에 함께 적용).
