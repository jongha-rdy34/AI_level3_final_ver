# 채점 기준 (창작 가정)과 검증 결과

공지·FAQ: 문항별 **요구사항 충족 + 풀이 과정**을 종합 평가하고 **최종 코드 리뷰**를 통과하면 Level 3. 문항은 **지시사항 구현형과 일정 성능 이상 달성형의 혼합**. 아래는 이 모의를 스스로 평가하기 위한 가정입니다.

## 1. 성능 기준 (`score_local.py`가 PASS/FAIL, 형식 오류는 0점)

| 문항 | 지표 | 기준 |
|---|---|---|
| Q3 (첫 제출) | test macro-F1 | ≥ 0.85 |
| Q4 (개선 제출) | test macro-F1 | ≥ 0.92 |
| Q5 | test 필드 정확도 / 스키마 위반 레코드 | ≥ 0.93 / 0건 (노트북의 dev 기준은 0.95) |

Q5 test에는 **끊긴 응답이 2건** 있습니다. 끊긴 응답은 복구하지 않는 것이 규칙(추측 금지)이라 정답 파이프라인의 test 상한이 약 0.946이고, 그래서 test 기준을 0.93으로 두었습니다.

### 기준을 정한 근거 (정답 노트북과 같은 파이프라인, CPU, seed 42)

| 설정 (모두 lr 1e-3~2e-3, 4~12 epoch) | val | val_small | **test** |
|---|---:|---:|---:|
| baseline: head만, 4 epoch, 증강 없음 | 0.584 | 0.438 | 0.492 ✗ |
| head만, 12 epoch, 증강 | 0.692 | 0.565 | 0.565 ✗ |
| stages.3 + head, 증강 | 0.902 | 0.767 | 0.800 ✗ |
| 전체, layer decay 0.75, **증강 없음** | 0.952 | 0.715 | 0.760 ✗ |
| 전체, layer decay 0.75, 증강 | 0.976 | 0.867 | 0.897 ✓ |
| 전체, decay 0.75, 증강 + mixup + 균형 샘플러 | 0.961 | 0.884 | 0.903 ✓ |
| **전체, layer decay 없음(1.0), 증강** | 0.979 | 0.902 | **0.927** ✓ |

(✓/✗는 Q3 기준 0.85. Q4 기준 0.92는 단일 모델 중 위 마지막 줄만 넘고, 나머지는 TTA·앙상블이 필요합니다.)

- **학습 범위가 가장 큰 요인**: head만(≤ 0.57) → 마지막 단계(0.80) → 전체(0.90~0.93)
- **축소 증강이 두 번째**: 같은 설정에서 증강을 빼면 test 0.897 → 0.760. test에 작게 찍힌 사진이 많아서입니다(val_small이 이 차이를 미리 보여 줌).
- **layer decay 0.75는 이 세트에서는 손해**(0.897 vs 0.927): 연습용 모델이 상품과 거리가 먼 **도형**으로 사전학습되어, 입력 쪽 층도 많이 바뀌어야 했기 때문으로 보입니다. 실제 TinyViT-5M은 ImageNet으로 사전학습되어 상품 사진과 가깝기 때문에 0.7~0.85가 흔히 도움이 됩니다. 결론: **layer decay는 1.0과 0.75 정도를 둘 다 시험해 validation으로 고르는 하이퍼파라미터**입니다.
- `val`(일반 검증)은 모든 상위 설정을 0.95 이상으로 보여 차이를 숨겼고, `val_small`의 순위가 test 순위와 같았습니다.

## 2. 요구사항 표

| 소문항 | 충족 조건 | 흔한 미충족 |
|---|---|---|
| 1-1 | 레이블 정규화(공백·대소문자·`-`·`_`), 모르는 값 None, 파일 없는 행 수, 정리 전 고유값 수, 불균형 비율 | `strip().lower()`만 해서 `T-Shirt`·`back pack`을 놓침 |
| 1-2 | `load()`까지 시도해 깨진 파일 판별, 모드·크기·md5 기록 | `Image.open`만 해서 잘린 파일을 정상으로 봄 |
| 1-3 | RGBA를 **흰 배경에 알파 마스크로 합성**, L·CMYK → RGB, 비율 유지 패딩, 물체 비율로 **train/test 차이 발견**과 의미 서술 | `convert("RGB")`만 해서 배경이 검게 됨, 정사각형으로 늘임 |
| 1-4 | 네 규칙 모두, 엇갈린 중복은 묶음 전체 제거, RGBA·L·CMYK는 버리지 않음 | 특이 모드 사진을 삭제, id가 아니라 행 순서로 파일 정보를 붙임 |
| 2-1 | 지정 순서, **`cfg`의 mean/std**(하드코딩 X), `fill=255`, 검증 변환은 결정적 | ImageNet 값을 직접 입력, fill 기본값(검정) |
| 2-2 | 한 번만 미리 읽기, `images` 재사용, long 정답, test는 -1 | epoch마다 파일을 다시 디코딩(느림), 정답 float |
| 2-3 | 층화, 표본별 역빈도 가중치, `replacement=True`, sampler·shuffle 동시 사용 안 함 | 비층화 |
| 2-4 | fill 이유, 축소 증강 ↔ 1-3 발견, 위험한 증강과 레이블 관계 | 근거 없는 서술 |
| 3-1 | `reset_classifier` 또는 `head.fc` 교체, 나머지 가중치 유지 | 모델 전체를 `pretrained=False`로 만듦 |
| 3-2 | 이름 접두어로 범위, **깊이별 lr(base × decay^깊이)**, 1차원 파라미터는 weight decay 0, 학습 파라미터만 그룹에 | 고정 파라미터까지 optimizer에, decay 방향이 거꾸로(입력 쪽 lr이 큼) |
| 3-3 | smoothing 분포 합 1, soft CE = `F.cross_entropy(label_smoothing)`와 일치, mixup은 입력·정답을 같은 lam·perm으로 | 정답만 섞음, `softmax` 후 `log` |
| 3-4 | warmup→cosine(step 단위), 고정 BN `eval()`, clip → step → scheduler 순서, 장치 일치 | scheduler를 epoch마다(값이 거의 안 변함), clip을 step 뒤에 |
| 3-5 | 최고일 때만 deepcopy, 끝에 복원 | 참조 저장 |
| 3-6 | baseline 대비 **근거 있는** 후보 2~3개(학습 범위·LLRD·증강·불균형), 선택 기준을 val 계열로 | test 점수로 선택, 여러 요소를 한꺼번에 바꿔 원인을 모름 |
| 3-7 | sample 순서(id로 `reindex`), `index=False`, 형식 통과 | test.csv 순서로 저장 |
| 3-8 | 수치 인용, 가장 효과가 큰 요소와 이유 | 수치 나열만 |
| 4-1 | 대각선 제외 상위 쌍, 클래스 이름으로, 틀린 사진을 직접 확인 | 대각선 포함 |

## 3. 코드 리뷰 체크리스트

- [ ] 함수가 한 가지 일을 하고, 핵심 결정(학습 범위·decay·증강·선택 기준)에 짧은 주석이 있다
- [ ] seed 고정, 커널 재시작 후 같은 결과
- [ ] test 정답·로컬 채점 점수를 학습·선택에 쓰지 않는다
- [ ] 원본 데이터 불변, 장치 일치, numpy 변환 전 `.cpu()`
- [ ] 제출 파일이 형식 점검을 통과하고 노트북 출력과 같은 실행에서 나왔다
- [ ] 서술 답안이 출력 수치와 일치하고 다음 행동으로 이어진다

## 4. 검증 결과 (2026-11-05, Windows 11, Python 3.12, torch 2.5.1 CPU, timm·torchvision 없음)
- **정답 노트북**: 모든 셀을 위에서 아래로 실행해 오류 없이 끝났습니다(CPU 약 6분). 출력(글자·그림)을 노트북에 저장했습니다. 로컬 채점 결과 **Q3 0.927 / Q4 0.955 / Q5 0.946 → 모두 PASS**. Q3 첫 제출 → Q4 개선 제출 +0.027.
- Q4 비교 (validation): 단일 0.979 / 0.902(val_small) → TTA 0.986 / 0.925 → seed 3개 앙상블 + TTA 0.987 / 0.944
- **버전 B(직접구현)**: 빈 상태로 끝까지 실행하면 처리되지 않은 오류 없이 끝나고, 소문항마다 `실패`를 출력하며 진행용 대체물로 이어 갑니다.
- **버전 A(빈칸)**: `___`은 정의되지 않은 이름이라 채우기 전에는 해당 셀에서 `NameError`(정상). 모든 빈칸 줄이 정답 코드의 한 줄과 대응하는지 자동 대조했습니다.
- **실제 torchvision 환경**(2026-11-06, Python 3.12.10 `.venv`, `requirements.txt` 설치: torch 2.5.1·torchvision 0.20.1 CPU)에서도 정답 노트북이 오류 없이 끝났습니다(약 5분). 로컬 채점 Q3 0.905 / Q4 0.939 / Q5 0.946 → 모두 PASS (Q3 → Q4 +0.034). 위 수치(tv_compat)와 조금 다른 것은 변환의 난수·보간 차이입니다.
- 이 작업 환경에서는 Jupyter 커널을 띄울 수 없어, 셀 코드를 순서대로 실행하는 스크립트로 검증하고 그 출력을 정답 노트북에 저장했습니다. timm·torchvision·GPU가 있는 환경에서는 실행해 보지 않았습니다.
